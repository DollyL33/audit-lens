Audit Lens

A one-page guide to how the app works and where to make changes. It's a snapshot of the code at the commit noted at the bottom, so it can drift as the project changes.

What it is

A Streamlit app that brings an internal/forensic auditor's eye to a messy spreadsheet. You upload a CSV or Excel file, approve suggested clean-up fixes with tick boxes, and get a dashboard: number cards, a monthly comparison, the biggest transactions, and two Nigrini audit tests (Benford's Law and same-same-same duplicates), each ending with a question to ask.

One page, three stagesapp.py shows upload → review → dashboard, remembering the stage in st.session_state.
Fix menuauditlens/fixes.py holds the only six changes ever made to data. Suggestions come from suggest.py (NVIDIA model, optional) or built-in rules.
Audit checksdetect.py finds the columns; metrics.py, benford.py, duplicates.py and questions.py do the analysis.

Follow one invoice: "$4,850.00" → the burgundy bar → the question

Reference route: three stops

Open each file in VS Code (Cmd+P, type the name) and search for the anchor. Shared as a reference route; you can walk it any time.

  1. auditlens/fixes.py, search def parse_number
    Turns "$4,850.00" into 4850.0 by removing $, commas, spaces and brackets ((120) → −120). It runs only when the "Turn Amount into numbers" fix is ticked, via apply_fixes.
  2. auditlens/benford.py, search def first_digits, then def run
    4850.0 → 4.85 → 4. run counts each first digit, compares it with EXPECTED (30.1% … 4.6%), marks spikes with z_statistic, and picks Nigrini's verdict from MAD_BANDS.
  3. auditlens/questions.py, search def benford
    Takes the most over-represented spike digit and builds the question. limit = (d + 1) * 1000 is why digit 4 asks about $5,000.

A practice to reuse

Write down what "working" looks like as something you can check, then make the check run automatically.

In this project, prd.md › Audit Finding: Benford's Law said: "a sample file with a planted spike on one digit is flagged" and "a file that follows Benford closely gets a 'looks normal' verdict." Those became test_messy_sample_flags_digit_4 and test_natural_data_looks_normal in tests/test_benford.py, run against made-up sample files with known answers (scripts/make_sample_data.py).

Writing tests this way caught real mistakes during the build: a column called "Note" was mistaken for an invoice number, and a tiny file's amounts were mistaken for IDs. Both were caught by tests before you ever saw them.

Next time: before asking an agent to build something, plant the answer. Make a small sample where you already know what the result should be (a duplicate you added yourself, a spike you created), and check the tool finds it.
